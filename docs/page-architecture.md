# 입찰체크 페이지 구성

## 1. 제품 내비게이션 원칙

입찰체크의 중심은 `공고`이며, 회사 프로필은 모든 공고 화면에 선택적으로 적용되는 전역 컨텍스트다.

사용자가 반복해서 경험하는 핵심 제품은 사실상 다음 두 화면이다.

```text
입찰공고 → 공고 상세
```

`회사 프로필 만들기`는 핵심 기능이지만 자주 방문하는 핵심 페이지가 아니다. 공고 목록과 상세의 분석 정확도를 높이는 설정 레이어로 취급한다.

```text
공고 탐색
  └ 회사 프로필 적용
       └ 같은 목록과 상세가 회사 기준 분석 화면으로 전환
            └ 결과를 저장할 때 로그인
```

따라서 `추천 공고`, `AI 분석`, `업체 조회`를 각각 독립된 1차 메뉴로 만들지 않는다. 사용자는 공고를 찾는 흐름을 벗어나지 않고 회사를 적용하고 분석 결과를 확인해야 한다.

### 페이지 우선순위

| 화면 | 핵심 역할 | 중요도 |
| --- | --- | --- |
| `/` | 서비스 이해와 검색 진입 | 중 |
| `/notices` | 공고 탐색과 회사 기준 필터링 | 최상 |
| `/notices/:noticeId` | 공고 이해와 참가요건 판단 | 최상 |
| `/company/setup` | 회사 조건 입력과 수정 | 지원 기능 |
| 로그인 후 관리 | 관심공고·알림·회사정보 관리 | 후순위 |

### 두 가지 핵심 사용자 흐름

프로필이 없는 사용자는 보던 공고 문맥을 유지한다.

```text
홈 → 입찰공고 → 공고 상세
                    ↓
               프로필 없음
                    ↓
             회사 프로필 만들기
                    ↓
          원래 공고 상세로 자동 복귀
                    ↓
                 자동 분석
```

이미 프로필이 있는 사용자는 목록부터 개인화된 경험을 받는다.

```text
입찰공고(회사 기준 결과)
  → 공고 상세
    → 상세 참가요건 자동 분석
```

## 2. 전체 사이트맵

### 공개 페이지

| 경로 | 페이지 | 핵심 목적 |
| --- | --- | --- |
| `/` | 홈 | 서비스 가치 이해 후 바로 공고 검색 |
| `/notices` | 입찰공고 | 전체 공고 검색, 업무 유형 필터, 회사 기준 검토 진입 |
| `/notices/:noticeId` | 공고 상세 | 공고 정보·참가요건 확인 및 회사 기준 판정 |
| `/company/setup` | 회사 프로필 만들기 | 사업자번호 조회 후 부족한 입찰 정보를 단계적으로 보완 |
| `/login` | 로그인(후속) | 프로필·관심공고·알림 저장이 필요한 시점에 인증 |

### 로그인 후 페이지

| 경로 | 페이지 | 핵심 목적 |
| --- | --- | --- |
| `/account/companies` | 회사 프로필 관리 | 여러 회사 추가·변경·삭제 및 기본 적용 회사 설정 |
| `/account/companies/:profileId` | 회사 프로필 상세 | 기본정보, 자격·인증, 실적·인력 관리 |
| `/account/saved-notices` | 관심 공고 | 저장한 공고 비교 및 진행 상태 관리 |
| `/account/alerts` | 알림 설정 | 회사별 검색 조건과 마감 알림 관리 |
| `/account/settings` | 계정 설정 | 사용자·조직·알림 수신 설정 |

## 3. 전역 레이아웃

### 헤더

```text
[입찰체크]  입찰공고                         [적용 회사 ▼] [로그인]
```

- 공개 헤더의 1차 메뉴는 `입찰공고` 하나만 강조한다.
- 회사 프로필은 메뉴가 아니라 전역 상태 선택기로 제공한다.
- 미적용 상태는 `+ 회사 적용`, 적용 상태는 회사명을 표시한다.
- `서비스 소개`는 홈 하단, `의견 보내기`는 푸터와 오류·판정 문맥 안에 둔다.
- 모바일에서는 로고, 회사 선택기, 메뉴 버튼만 유지한다.

### 회사 프로필 전역 상태

회사 프로필은 어느 공고 화면에서도 변경할 수 있다.

```text
미적용: 전체 공고 탐색 중 · [+ 회사 적용]
적용:   ABC 주식회사 기준 · 임시 프로필 · [변경] [저장]
```

회사 적용 팝오버에서는 사업자등록번호 입력과 기존 프로필 선택만 제공한다. 상세 정보 보완은 `/company/setup`에서 처리해 작은 팝오버가 복잡해지지 않게 한다.

프로필 적용은 상세에서 시작하는 일회성 기능이 아니다. 한 번 적용한 프로필은 `/notices`와 모든 `/notices/:noticeId`에 즉시 반영한다.

## 4. 공개 페이지 상세

### 4.1 홈 `/`

홈은 설명용 랜딩 페이지이면서 실제 서비스 진입점이다.

```text
Header
Hero: "회사를 등록하면, 참여할 수 있는 공고를 골라드립니다"
통합 공고 검색
회사 적용 CTA
분석 결과 예시
신뢰 원칙: 근거·기준일·확인 필요
이용 방법 3단계
Footer
```

원칙:

- 첫 화면 안에 공고 검색창을 노출한다.
- 회원가입 CTA보다 `공고 검색`과 `회사 적용`을 먼저 보여준다.
- 실제 데이터가 아닌 숫자형 추천 결과를 데모처럼 표시하지 않는다.
- 랜딩의 공고 목록은 제거하거나 최대 3개만 노출해 본 화면과 역할이 중복되지 않게 한다.

### 4.2 입찰공고 `/notices`

서비스의 핵심 작업 화면이다.

```text
페이지 제목 + 나라장터 API 제공 범위 안내
회사 상태 바
업무 유형: [전체] [물품] [용역] [공사] [외자] [기타]
공고명·발주기관 검색
전체 공고 수 + 페이지당 표시 개수
공고 리스트
페이지네이션
```

공고 한 건만 읽어도 1차 검토가 가능해야 한다.

```text
[용역] 서울시 정보시스템 유지관리 용역
공고번호 · 게시 9월 9일 11:11
서울특별시 · 일반경쟁 | 3.2억원 | D-4 · 마감 9월 13일 10:00
                                      [회사 선택 후 확인]
```

목록에서 단순히 공고명·기관·금액·마감일만 보여주지 않는다. 회사 적용 시에는 판정에 영향이 큰 조건 2~3개와 전체 요약을 함께 보여준다.

회사 미적용 상태:

- 상태 탭과 적합도 정렬을 비활성화한다.
- 비활성 이유와 `회사 프로필 적용` CTA를 함께 제공한다.
- 공고명, 기관, 금액, 지역, 계약방법, 마감일을 보여준다.

회사 적용 상태:

- 현재 페이지 공고를 한 번에 평가한다.
- `충족`, `미충족`, `확인 필요` 개수와 주요 문제 요건을 최대 2개 표시한다.
- 요건 추출 전 등 공고별 평가 오류는 목록에서 원인을 안내한다.
- `상세 검토`를 통해 전체 요건과 근거를 확인한다.
- 프로필을 한 번 만든 사용자는 이후 방문에서도 목록 진입과 동시에 회사 기준 결과를 받는다.

데스크톱은 한 행이 하나의 공고인 리스트, 모바일은 독립 카드로 렌더링한다. 단순 CSS 재배치에 의존하지 않는다.

### 4.3 공고 상세 `/notices/:noticeId`

공고 원문 열람 페이지가 아니라 입찰 검토 화면으로 설계한다.

```text
목록으로 돌아가기
공고 제목 · 기관 · 공고번호 · 게시시각(KST)
핵심 정보: 예산 · 계약방법 · 입찰방법 · 접수마감(KST)
일정 미정 안내(필요 시)
회사 상태 및 전체 판정 요약
요건별 판정 카드
나라장터 원문
```

프로필이 있으면 별도의 `AI 분석` 버튼을 누르게 하지 않는다. 상세 진입과 동시에 분석을 시작하고 `분석 중 → 분석 완료 또는 실패` 상태를 인라인으로 보여준다.

회사 미적용 시에는 공고 요구사항과 근거만 보여주고 충족 여부는 표시하지 않는다. 요건 영역 상단에 `우리 회사 기준으로 확인` CTA를 둔다.

```text
우리 회사가 이 공고에 참여할 수 있는지 확인해보세요.
지역 · 업종 · 기업구분 · 인증 · 자격요건을 공고 조건과 비교합니다.
[회사 프로필 만들기]
```

이 CTA에는 현재 상세 주소를 `returnTo`로 전달한다. 프로필 생성 또는 로그인 완료 후 홈이나 목록으로 보내지 않고 원래 상세로 복귀시킨다.

회사 적용 시 각 요건 카드는 아래 흐름을 유지한다.

```text
공고 요구사항 → 회사 정보/증빙 → 판정 → 판정 근거
```

`입찰 가능`, `입찰 가능성 높음`은 법적·최종 결론처럼 보일 수 있으므로 기본 UI 라벨로 사용하지 않는다. 목록 요약에는 `주요요건 충족`, `확인 필요`, `명확한 미충족`, 개별 조건에는 `충족 / 미충족 / 확인 필요`를 사용한다. 향후 종합 가능성 표현이 필요하면 판정 범위와 면책 문구를 함께 검증한 후 도입한다.

### 4.4 회사 프로필 만들기 `/company/setup`

로그인 없이 시작할 수 있는 짧은 설정 페이지다. 전체 프로필 완성을 요구하지 않는다.

```text
1. 사업자등록번호로 회사정보 조회
2. 조회된 회사 확인 후 적용
3. 원래 보던 공고 또는 입찰공고 목록으로 복귀
```

- 적용한 회사는 브라우저 localStorage에 임시 저장한다.
- 진입 시 `returnTo`를 받고 적용 완료 후 해당 문맥으로 복귀한다.
- 자격·인증·면허·실적을 직접 보완하는 기능과 로그인 저장은 후속 범위다.

### 4.5 로그인 `/login` (후속 범위)

로그인은 독립적인 서비스 진입점이 아니라 저장 동작의 연장선이다.

```text
"분석 결과와 회사 프로필을 저장하세요"
[카카오] [네이버] [이메일]
로그인 없이 계속 보기
```

인증 성공 후 사용자가 하던 작업으로 돌아가야 한다. `returnTo`와 저장하려던 대상 정보를 보존한다.

## 5. 로그인 후 페이지 상세

### 5.1 회사 프로필 관리

- 카드 목록보다 회사 전환이 쉬운 간결한 리스트를 사용한다.
- 한 사용자가 여러 프로필을 관리할 수 있다.
- 사용자 계정과 회사 엔티티를 동일시하지 않는다.
- 회사별 `프로필 완성도`, `마지막 확인일`, `보완 필요 항목`을 표시한다.

### 5.2 관심 공고

- 단순 북마크 목록이 아니라 `검토 전 / 검토 중 / 참여 결정 / 제외` 상태를 관리한다.
- 마감 임박, 공고 변경, 부족한 회사 정보가 우선 보이게 한다.
- 회사 프로필별로 분리해 볼 수 있어야 한다.

### 5.3 알림 설정

- 회사 프로필과 검색 조건을 조합해 알림을 만든다.
- 즉시, 일간 요약, 마감 임박 알림을 구분한다.
- MVP에서는 이메일만 지원하고 채널 확장을 전제로 데이터 모델을 설계한다.

## 6. 만들지 않을 페이지

- 별도 `추천 공고` 페이지
- 별도 `AI 분석` 페이지
- 로그인 직후 빈 대시보드
- 공개 영역의 독립적인 `업체 조회` 1차 메뉴
- 공고와 분리된 판정 결과 페이지

이 기능들은 공고 목록·상세 또는 회사 프로필 관리에 포함한다.

## 7. 공통 상태 설계

모든 핵심 페이지는 다음 상태를 별도로 디자인한다.

- 로딩: 레이아웃을 유지하는 skeleton
- 결과 없음: 조건 초기화와 대체 검색 제안
- 오류: 원인 요약, 재시도, 의견 보내기
- 부분 데이터: 확인된 정보와 확인 불가능한 정보 구분
- 오래된 정보: 마지막 확인일과 다시 확인하기
- 비로그인 저장 시도: 현재 작업을 보존한 로그인 유도

## 8. 구현 순서

### 1차: 공개 탐색 경험

1. 입찰공고와 공고 상세를 하나의 UX로 완성
2. 전역 회사 상태와 자동 분석 상태 연결
3. 상세에서 프로필 생성 후 원래 공고로 복귀하는 흐름 구현
4. 짧은 회사 프로필 만들기 페이지 구현
5. 완성된 핵심 화면을 기준으로 홈 정리

### 2차: 저장과 재방문

1. 로그인과 원래 작업 복귀
2. 회사 프로필 관리
3. 관심 공고
4. 알림 설정

### 3차: 운영 확장

1. 여러 사용자와 조직 권한
2. 회사별 검토 이력
3. 서류·유효기간 관리
4. 컨설턴트용 다회사 작업 공간

## 9. MVP 확정 범위

첫 번째 UI 개편의 제품 검증 대상은 두 화면이다.

1. 입찰공고
2. 공고 상세

회사 프로필 만들기와 홈은 이 두 화면을 지원하는 최소 범위로 구현한다. 로그인 화면은 저장 CTA에서 진입 가능한 최소 형태로 두고, 계정 관리·관심 공고·알림은 공개 탐색 경험이 검증된 뒤 구현한다.

## 10. 구현 전제

`/notices`에서는 현재 페이지 공고 ID를 `assess_company_bid_eligibilities`에 한 번 전달한다. 상세 평가 API를 공고 수만큼 클라이언트에서 호출하지 않는다.

필요한 목록 응답 최소 형태는 다음과 같다.

```ts
type NoticeAssessmentPreview = {
  noticeId: string
```

- 서버에서 현재 페이지 공고를 한 번에 평가한다.
- 목록은 빠른 1차 판단, 상세는 모든 조건과 근거를 보여주는 전체 판단으로 역할을 나눈다.

## 11. 기관·업체 분석 첫 화면

공개 분석 메뉴 `/organizations`와 `/companies`는 검색 전 첫 화면의 목적을 구분한다.
기존 기관명·기관코드 검색과 분야·제품·업체명·사업자번호 검색을 유지한다.

### 업체 탐색 개편

`/relations`는 검색·연도·분야 필터, 인터랙티브 네트워크, 선택 노드 분석 패널로 구성한다.
화면은 최대 너비 1440px와 바깥 여백을 두며, 소개 영역과 별도 화면 제목을 제거한다.
검색·조건 바 바로 아래에 화면 높이에 맞춘 그래프(데스크톱 520–780px, 좁은 화면 520px)를 배치한다.
노드·관계 목록과 상위 5·10·20개 설정은 그래프 내부 왼쪽 아래 도구 모음에 두고
확대·축소·전체 보기는 오른쪽 아래에 둔다. 조회 필터에는 업무구분·기간·분야·지역만 둔다. 초기에는 패널을 접고 그래프가 카드 전체 너비를 사용한다. 데스크톱 선택 시 그래프와 패널을
약 75:25로 배치하고 좁은 화면은 하단 Dialog로 표시한다. 관계 탐색 메뉴에서는 헤더의
전역 검색을 숨기고 작업 화면의 통합 검색 하나를 사용한다. 기존 `seed_type`, `seed_id`,
`seed_name` 주소도 탐색 중심으로 읽는다.

검색·필터는 기존 상세 화면의 `EntityDetailContextBar`를 재사용해 헤더 아래에 sticky로 고정한다.
기본은 검색·최종 조회 버튼·선택 조건 요약만 표시하고 `조건 변경`에서 필터를 펼친다.
업체 상세의 `ProcurementFilterPanel`과 `SearchableSelect`를 재사용해 기간 슬라이더,
대분류·세부분야/품목 선택, 선택 조건 칩을 제공한다. `useExplorerFilters`가 후보와 필터를
임시 보관하며 검색 결과 선택·분류 변경·칩 삭제는 조회 버튼 전까지 그래프와 URL에 반영하지 않는다.
분류 후보를 위한 프로필은 기존 캐시를 공유하며, 현재 목록은 업체·기관 실적에서 확인한 분류다.
최종 조회 시 조건을 한 번에 URL로 적용하고 뒤로 가기에서도 선택을 복원한다.
분야 선택은 필수이며 전체 분야를 기본 분석하지 않는다.
분야 미선택 상태에서는 선택한 기관·업체의 분야 목록용 프로필만 조회하고 2단 확장과
경쟁업체 조회를 시작하지 않는다. 조회한 전체 분야 후보는 기존 요청 캐시에서 유지한다.

기관에서 계약업체 기본 10곳(5·10·20곳 선택), 각 업체에서 다른 거래기관 최대 2곳을 자동 표시한다.
기관 시작 시 최대 31개, 업체 시작 시 관측 경쟁업체 5곳을 포함해 최대 36개 노드가 기본 한도다.
중심 관계를 20곳으로 늘리면 각각 최대 61·66개이며 중복은 제거한다. 화면에 실제 노드·관계
표시 수와 중심 관계 목록의 총 개수, 상위 표시 한도를 명시한다. 전체 관계를 모두 표시하는
방식은 아니다. 분야 시작은 표본 내 주요 기관 5곳과 기관별 업체 3곳, 최대 21개를 유지한다.
2단 관계는 클릭을 기다리지 않고 병렬 조회한다. 최초 조회 중에는 단계별 진행 상태를
표시하며 모든 2단 조회가 완료되거나 실패한 뒤 그래프를 한 번에 배치한다. 실패한 분기는
오류와 재시도를 제공하고 확인된 관계만 표시한다. 이 표시 방식은 Teoria의 첫 조회 지연을
줄이는 최적화가 아니다. 관계 탐색은 과거 Cytoscape 페이지의
어두운 우주 형태를 복원한다. 기관은 보라색 원, 업체는 청록색 원, 분야는 파란색 원으로 구분한다.
업체 중심 그래프의 경쟁 업체도 계약금액 확인 여부와 관계없이 청록색 업체 노드로 표시한다.
검색한 기관·업체는 화면 중앙에 놓고 고정하며 주변에는 도형과 아래 이름표를 표시한다.
그래프 안에서 전체·기관·업체 표시를 전환해도 검색한 중심 대상은 유지한다. 별도의 관계를 추정하지 않는다.
기관·업체 원의 면적은 표시된 계약금액 합계에 비례하고, 선은 해당 관계의 확인된 값을 반영한다.
전체 시장 실적과 동일하다고 해석하지 않는다. 분야 중심만 고정 크기이며 누락된 금액은 최소 크기와
흐린 채움으로 구분한다. 경쟁 업체는 계약금액이 아직 조회되지 않아도 업체 공통 색상으로 표시한다.
같은 입찰 참여는 계약 지표에 섞지 않는다.
직접 관계와 다음 관계를 동심원으로 배치한다. 짙은 남색 배경에 작은 별과 은은한
중심 광원을 사용하며 링크 선택 시 해당 선과 양쪽 노드를 강조한다.
주변 노드는 최대 20fps, 3–4px 범위에서 천천히 움직이고 중심 노드는 고정한다.
그래프에 포인터가 올라오거나 관계가 선택되거나 탭이 숨겨지면 움직임을 멈춘다.
모션 감소 설정에서는 애니메이션을 시작하지 않는다. 드래그한 노드는 새 위치를 기준으로 움직인다.
화면 문구에는 2단·노드·관측·Runtime 같은 구현 용어를 쓰지 않는다. 로딩은 `거래 정보를 불러오고 있습니다`,
경쟁 목록은 `같은 입찰에 참여한 업체`로 표현한다. 수집 기록·일부 계약·공동계약의 금액 기준은 쉬운 설명으로 유지한다.
기관에서 시작하면 계약업체와 그 업체의 다른 거래기관을 보여준다. 업체에서 시작하면
해당 업체의 거래기관 전체와 사용자가 선택한 수만큼의 동일 입찰 참여 상위 업체를 보여준다.
경쟁 업체의 발주기관은 사용자가 표시를 선택했을 때 조회해 보여준다.
업체 거래기관은 선택한 필터로 프로필을 끝 페이지까지 조회하며, 너무 많은 요청이 한꺼번에 몰리지 않도록
나머지 페이지는 5개씩 병렬로 읽는다. 계약 건수가 없는 기관 행은 계약 관계로 연결하지 않는다.
그래프는 검색한 대상을 중심으로 직접 관계와 다음 관계를 여러 동심원에 나눠 놓는다. 업체 중심에서는
첫 번째 원에 경쟁 업체, 두 번째 원에 선택 업체와 계약 이력이 있는 발주기관, 세 번째 원에 경쟁 업체에만
연결된 나머지 발주기관을 놓는다. 기관 노드는 `발주기관`으로 표시하고 정확한 계약 이력 범위는 위치와
툴팁으로 구분한다. 노드 색상과 외곽선은 중심 유형과 관계없이 엔티티 종류별 공통 표현을 사용한다.
세 번째 원은 기본으로 숨기고 `경쟁 업체 발주기관` 버튼을 선택했을 때 표시한다.
한 단계에 발주기관이 많으면 기관 중심 그래프와 같은 기준으로 가까운 보조 원에 나눠 밀도를 맞춘다.
그래프 전체 보기 동작은 현재 표시된 노드 전체를 화면에 맞춘다.
기관과 업체 중심 탐색은 표시할 거래 업체 또는 경쟁 업체 수를 상위 5·10·20개 중 선택하며 기본은 20개다.
업체 검색 화면에는 계약기관 수와 표시한 경쟁사 수/조회된 경쟁사 수를 구분해 보여준다.
동일 기관에 계약했다는 사실만으로 경쟁사로 분류하지 않는다. 공동 참여 업체와 거래기관은
기존 분석 API로 조회하므로 일부 응답은 네트워크 snapshot과 다를 수 있다. 노드는
type·id로 중복 제거하고 확인된 관계만 종류를 구분해 연결한다. 같은 기관·분야의 계약업체라는
이유로 직접 경쟁이라고 표시하지 않는다. 관계의 요약은 미리 조회하며 `여기서 탐색`으로
중심을 바꿀 수 있다. 필터 변경 시 선택과 확장을 초기화하고 뒤로 가기로 복원한다.

노드 쌍마다 관계선은 하나만 표시한다. 기관·업체의 거래선에 계약·낙찰·참여 집계를 함께
보관하고 클릭 시 두 노드의 계약금액·건수, 낙찰·관측 참여, 최근 계약일과 대표 공고를
묶어 표시한다. 링크 선택은 노드 선택과 별도 URL 상태로 관리하고 단일 링크만 강조한다.
`ExplorerRelationshipPanel`은 해당 쌍의 데이터와 근거만 제공하며 전체 업체·기관 프로필을
조회하지 않는다. 노드를 명시적으로 선택할 때 `ExplorerInspector` 또는 분야 패널을 연다.
계약 근거도 해당 쌍으로 조회한다. 공동 참여와 분야 연결은 각각의 두 노드
관계로 구분한다. 이전 관계 종류가 포함된 URL의 선택 상태도 복원한다. 공동 참여는
`analyze_company_competitors`의 관측값이며 업체 쌍별 승패로 해석하지 않는다. 공동 참여 관계를
선택하면 두 업체의 참여 기록에서 공고 ID가 일치하는 대표 공고와 상세 링크를 보여준다. 노드·관계 목록은
키보드로도 선택할 수 있다. 휠은 입력 단위를 정규화해 포인터 위치를 중심으로 확대한다.

검색은 `ExplorerSearch` 자동완성으로 제공하며 250ms 입력 대기 후 Teoria의
`autocomplete_procurement_entities`에서 공고·기관·업체 후보를 조회한다. 한 번에 20개씩
받고 cursor로 다음 결과를 펼친다. 분야·품목은 공식 분류 카탈로그에서 함께 검색한다.
공고 선택 시 Runtime이 적용 가능하다고 표시한 업무구분·분야와 명시된 기관 코드만
조회 조건에 채운다. 선택 항목명은 검색창에 표시하고 최종 `조회` 버튼을 제공한다.
한글 조합 중에도 250ms 입력을 멈추면 후보를 조회하고, 조합 중 Enter로 선택하지 않는다. 입력 변경 시
이전 요청을 취소하고 창이 닫히면 조회를 중단한다. 입력하는 동안 분석 URL과 네트워크를
바꾸지 않으며 조회 버튼으로 확정할 때만 검색어와 필터를 URL에 적용한다. 검색창은 필터와 별도 행을 사용하고
필터는 펼친 패널에서 고정 그리드 너비로 배치한다. 공식 분야 결과는
다른 자동완성 결과의 완료를 기다리지 않고 표시한다. 키보드 이동·선택과
Escape 닫기를 지원한다. 기존 업체 탐색의 계약 검색 기능은 유지하지만 자동완성에서
중복 계약업체 검색을 추가 호출하지 않는다. 업무구분과 카테고리, 기간은
모든 분석에 동일하게 적용한다. 공고 선택은 `/explorer/notice-context/{notice_id}`에서
확인한 기관과 업무구분·공식 분야를 URL에 적용하며, 누락 분류는 Teoria의 공고 참여 분석
`analysis_basis.field_filter`로 보완할 수 있는 경우만 사용한다. 기관명을 보고 소재지를
추정하지 않는다. 현재 Runtime은 지역 필터를 지원하지 않아 지역 선택은 비활성화하고
명시적 소재지 원천값이 없는 경우 미확인으로 표시한다.

업체 패널은 주요 거래기관 Treemap, 관측 공동 참여 업체, 최근 계약·참여·낙찰과 관측
낙찰률을 제공한다. 기관 패널은 주요 거래업체 Treemap, Runtime의 상위 5개 계약금액 비중,
신규 관측 업체, 최근 공고·계약을 제공한다. Treemap은 조회한 상위 최대 5개 관계의 확인된
양수 귀속금액만 사용하며 전체 시장 점유율로 표시하지 않는다.

분야/품목 검색 `/explorer/fields`는 Runtime 공식 분류 카탈로그를 사용한다. 공식 품목
코드를 선택하면 `/explorer/network`가 최대 2단계의 계약 관계를 일괄 조회하고,
`/explorer/field-market`이 Runtime 수집 범위 내 전체·연도별 계약 집계를 제공한다.
기관–업체 링크 근거는 네트워크와 같은 snapshot의 `network_edge` 모드로 조회한다.
대분류·중분류만 선택했을 때는 기존 제한된 계약 표본 경로를 유지한다. 네트워크의
낙찰·참여·동시 참여·공동수급과 지역 필터는 Runtime 읽기 모델에서 지원하지 않는다.

기관·업체 검색은 별도로 표시해 공고 검색 완료를 기다리지 않는다. 그래프와 분석 패널은
공통 query options를 사용해 같은 조회 크기의 요청 캐시를 공유한다. 계약 근거 목록은
관계선 선택 또는 근거 버튼을 누를 때 조회한다. 분야 선택값은 탐색 중심의 공식 분류에서 제공하며 키워드를 공식 분야로 자동 변환하지
않는다. 모든 관계·분석·근거 요청에 같은 기간·분야·업무구분을 전달한다. 검색 결과의
실적 업체는 계약 검색 표본이다. 분석 패널은 선택 노드 요약과 연결된 기관·업체 관계의
페이지별 계약 근거를 제공하고 기존 상세로 이동할 때 조회 조건을 보존한다.

`/companies`는 검색 하나, 시각적인 업체 후보 목록, 선택 업체 분석 패널로 구성한다.
검색 전에는 검색창과 예시를 우선 표시하고 기존 주요 분야 탐색은 펼쳐서 볼 수 있다.
사업 분야 검색은 실제 계약 검색에서 업체를 찾으며 업체명·사업자등록번호 검색도 유지한다.
선택 전 목록은 전체 너비를 사용한다. 데스크톱은 선택 후 우측 패널을 열고 모바일은
포커스 관리와 Escape 닫기를 지원하는 하단 Dialog로 표시한다.

계약 검색 후보는 금액순 최대 100건에서 확인한 표본이다. 전체 시장 순위로 표시하지 않는다.
목록은 표본 내 관련 계약 건수 또는 대표 계약금액으로 정렬한다. 금액 막대는 대표 계약의
전체 금액이며 업체 귀속 금액 합계가 아니다. 누락 금액을 0으로 채우지 않는다.
검색어별 귀속 금액 집계와 지역 필터가 Runtime에 없으므로 이를 제공한다고 표시하지 않는다.

우측 패널은 검색 계약 근거와 기간 전체 분야 프로필의 범위를 명시적으로 구분한다.
프로필에는 계약금액·건수·거래기관, 연도별 계약금액, 관측 낙찰률과 공동 참여 업체를 표시한다.
공동 참여 업체 선택은 관측 횟수와 상세 연결을 제공하며 미제공 업체 쌍별 결과는 추정하지 않는다.
최대 3개 업체의 기간 전체 실적 비교를 지원한다. 검색어·기간·정렬·선택·비교 후보는 URL에
보존하며 검색 또는 기간 변경 시 선택과 비교를 초기화한다. 기존 업체·기관·공고 상세는 유지한다.

### 기존 주요 분야 분석

업체 상세 개요는 관계·수주 분석을 우선 표시한다. React Flow 네트워크에는 중심 업체
1개, 귀속 계약금액 기준 주요 거래기관 최대 5개, 관측 공동 참여 업체 최대 5개를 표시한다.
계약 관계는 실선, 공동 참여 관계는 점선으로 구분하며 확인되지 않은 기관·경쟁업체 사이의
관계를 추가하지 않는다. 확대·축소·화면 맞춤과 별도의 키보드 선택 목록을 제공한다.

기관 선택 시 같은 기간·분야·업무구분으로 기관 프로필을 조회한다. Apache ECharts
Treemap은 조회된 상위 최대 30개 업체의 양수 귀속 계약금액만 면적으로 비교한다.
전체 시장 점유율이나 미조회 업체의 나머지 금액을 추정하지 않으며, 누락·0 금액도
대체 목록에서 확인할 수 있다. 노드·선택 기관·Treemap 업체 선택은 URL에 보존한다.
연도별 막대는 중심 업체의 계약금액을 나타내며 확인된 0과 누락 연도를 구분한다.
차트는 정확한 수치 목록과 상세 근거 연결을 함께 제공한다.

네트워크만 어두운 배경을 사용한다. 시각화 모듈은 상세 개요에서 지연 로딩하며 ECharts는
Bar·Treemap과 필요한 컴포넌트·SVG 렌더러만 등록한다. 기존 분야별 실적·참여 추이·거래
구조 상세 통계는 펼침 영역에 유지하고, 입찰 이력·발주기관·업체 정보 탭은 유지한다.
기관→분야→업체별 결합 금액은 기존 API에서 검증되지 않아 Sankey는 아직 제공하지 않는다.

물품·용역·공사를 각각 독립된 섹션으로 펼친다. 직전 완료 연도를 기준으로 유형별
공식 분야 최대 2개, 분야별 실적 업체 최대 3곳을 보여준다. 각 업체에는 해당 분야의
업체 귀속 계약금액·계약건수·거래기관 수·주요 거래기관을 표시한다.

- `/api/v1/home/company-sectors`는 유형별 금액순 계약 최대 100건에서 후보 분야를
  선택한다. 계약금액은 현재 계약금액을 우선하며 원시 계약을 합산하지 않는다.
- 물품 계약에 공식 분류가 없으면 후보 계약업체 최대 6곳의 Teoria 프로필에서
  공식 물품 분야를 찾는다. 같은 분야명은 중복 노출하지 않는다.
- 분야별 후보 업체는 Teoria의 업체 프로필에 연도·업무유형·분야 조건을 적용해
  다시 조회한다. 전체 업체 실적을 분야 실적처럼 표시하지 않는다.
- 분야명은 분야 검색으로, 업체명은 연도·유형·분야를 보존한 업체 상세로 연결한다.
- 제한된 계약과 후보 업체를 탐색한 결과다. 전체 시장 분야 규모나 업체 순위,
  품질 평가 또는 추천으로 표현하지 않는다.

### 기관 분석

기관별 계약업체 트리맵을 하나씩 보여주는 수동 캐러셀을 제공한다. 자동 재생이나
기관 탭 없이 이전·다음 버튼, 다음 기관명, 현재 위치·전체 개수와 좌우 스와이프로 탐색한다.

- `/api/v1/home/relationships`는 최근 90일 낙찰 최대 100건에서 확인된 기관 기본
  12곳을 찾아 목록을 먼저 표시한다. 현재 기관의 최근 3개년 계약업체 최대 30곳만
  별도 조회한다. 최대 24곳까지 더 불러올 수 있다.
- 맵은 확인된 업체 귀속 계약금액에 비례한다. Runtime 전체 귀속 집계와 비중 계산 가능
  여부가 확인될 때만 전체 비중과 기타를 표시한다. 누락 금액을 0으로 만들지 않는다.
- 첫 화면에서는 큰 칸의 업체명·비중과 작은 칸의 이름만 표시하고 분석 상세는 열지 않는다.
- 신규 관계는 주요 업체 목록에서 추정하지 않고 `search_organization_supplier_entries`의
  종료 연도 `first_observed`를 기관별 최대 3곳 별도로 조회해 일치하는 업체에 표시한다.
  표시 연도를 명시하며 실제 최초 거래로 단정하지 않는다.
- 기관 검색 결과와 기존 기관 상세 경로는 유지한다. 가상 데이터 샘플과 샘플 링크는 제거했다.

계약 통계는 Teoria 집계값을 사용하고, 금액 미확인을 0으로 대체하지 않는다.
부분 데이터·일부 조회 실패·정상적인 빈 결과를 구분한다. 첫 화면에서 기간과 업무유형을
조정하는 필터는 두지 않으며 상세 분석에서 조정한다.

이 공개 분석 메뉴는 기존 MVP에서 제외했던 독립 업체 조회 메뉴를 확장한 현재 구현이다.
공고와 참가요건 검토의 중심 역할 및 선택 회사의 전역 컨텍스트 원칙은 유지한다.

### 분석 조회 속도

첫 화면은 백그라운드에서 준비한 목록 스냅샷을 사용하고 목록 갱신 시각을 표시한다.
부분 데이터 상태도 보존해 재사용하며 조회 중 같은 분석을 중복 실행하지 않는다.
상세 화면은 같은 조건의 읽기 전용 분석 결과를 짧게 재사용한다. 업체 정보 탭을 열기 전에는
공식 자격·기업 정보 조회를 시작하지 않고, 기관 계약업체 탭에서는 공고 활동 조회와 신규
업체 전체 목록 조회를 생략한다. 신규 업체 목록은 해당 필터 선택 시 불러온다.
